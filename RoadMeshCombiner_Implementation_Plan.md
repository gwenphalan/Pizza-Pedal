# Road Mesh Combiner - Implementation Plan

## 2a. Workshop & Dialogue Section

_This section documents the final design decisions._

1.  **Chunk Size:** What should the default size (in world units, e.g., 100x100) for each combined mesh chunk be?

    - **Decision:** Start with a configurable `100x100` size.

2.  **Material Grouping:** Should different road line types be combined?

    - **Decision:** Yes. Since all road tiles use a single material, they can be combined. The combiner will group all road-related tiles together.

3.  **Source Tile Handling:** What should happen to the original, individual tile GameObjects?

    - **Decision:** (A) They will be destroyed immediately after combining.

4.  **Workflow Trigger:** How should the combination process be initiated?

    - **Decision:** (A) A manual button in the `RoadBuilder` inspector (e.g., "Combine Road Meshes").

5.  **Sidewalk & Curb Handling:** How should sidewalk and curb tiles be handled?

    - **Decision:** (B) They will be combined into a _separate_ set of chunks from the roads.

6.  **Collider Generation:** Should this script also be responsible for generating colliders?

    - **Decision:** (A) No, the combiner will only handle meshes. Colliders will be managed by a different process.

7.  **Editor Progress Bar:** Is an editor progress bar needed?

    - **Decision:** (B) No, it's an unnecessary complexity for now.

8.  **Implementation Order & Sidewalks:** How to handle the future sidewalk system?

    - **Decision:** (A, with skeleton for B) Implement the combiner now to handle roads, but structure the code with a reusable core function. This makes it trivial to add a second call to combine sidewalks later once they are being generated by `RoadBuilder`.

9.  **Hierarchy of Combined Objects:** How should the new objects be organized?
    - **Decision:** (A) A single root GameObject (e.g., "Optimized World") will be created with two children: "Road Chunks" and "Sidewalk Chunks".

## 1. Title & Overview

**Road Mesh Combiner**
This system will optimize the procedurally generated road network by combining thousands of individual road tile meshes into a smaller number of chunk-based meshes. This will drastically reduce draw calls while preserving LODs and enabling efficient frustum culling, leading to a massive performance increase.

## 3. Core Vision & Goals

- **Goal:** Reduce the number of draw calls for the road network from thousands to dozens.
- **Feel:** The optimization should be transparent at runtime. The visual appearance of the road network, including LOD transitions, should be identical to the pre-combined version.
- **Mechanics:** The system will partition the world into a grid. All tiles of a similar type within a grid cell ("chunk") will be combined. This process will be repeated for each LOD level.

---

## 4. Proposed Architecture

1.  **`RoadTileInfo.cs` (New Component):**
    - A simple data component attached to each generated tile.
    - **Responsibility:** "Tags" each tile with its type, allowing the combiner to selectively group meshes.
2.  **`RoadBuilder.cs` (Modified):**
    - **Responsibility:** Will be updated to attach and configure the `RoadTileInfo` component on every tile it instantiates.
3.  **`RoadBuilderEditor.cs` (New Editor Script):**
    - A `CustomEditor` for `RoadBuilder`.
    - **Responsibility:** To add a "Combine Road Meshes" button to the `RoadBuilder` inspector, which will call the static `RoadMeshCombiner`.
4.  **`RoadMeshCombiner.cs` (New Static Editor Class):**
    - A static utility class.
    - **Responsibility:** Contains the core logic for finding tiles, partitioning them, and combining them into LOD-aware, chunked meshes. It will be designed with a reusable core function that can be called for different sets of `TileType`.

---

## 5. Implementation Roadmap

1.  **Phase 1: Tagging**
    - Create `RoadTileInfo.cs`.
    - Modify `RoadBuilder.cs` to use `RoadTileInfo`.
2.  **Phase 2: Combiner Logic**
    - Create the static `RoadMeshCombiner.cs` utility class.
    - Implement the core, reusable combining function `Combine(List<TileType> typesToCombine, ...)` which performs the chunking and LOD-aware mesh combination.
3.  **Phase 3: Editor UI**
    - Create the `RoadBuilderEditor.cs` script.
    - Add the inspector button, which will call `RoadMeshCombiner.Combine()` for road tiles. It will be structured to easily add a second call for sidewalk tiles in the future.
4.  **Phase 4: Finalization & Cleanup**
    - Implement the logic to destroy the original source tiles after combination.
    - Add console logs to report on the results of the combination.
